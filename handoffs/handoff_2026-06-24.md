## Section A -- Model-health: calibration coverage + no-edge retirement

Goal: investigate why some systems consistently lose. Pulled ops data via
`/model-health`, `/edge-analysis`, `Gates/model_gates.json`, Cloud Run logs, and
direct `bets`-table queries (Cloud SQL proxy from Cloud Shell).

**Root cause.** Losses dominated by model overconfidence on large "edges"
(the documented adverse-selection curve). Acute fixable part: two live systems --
**PITCHER_ER** and **F1H** -- bypassed the prediction-calibration + `EDGE_CAP`
layer entirely. Post-06-11 they leaked the toxic big-edge bets every *wired*
system suppressed (PITCHER_ER placed 55/65 `>0.20`-edge bets, overconf +0.129 on
n=190; F1H 3/3, +0.113 on n=95). Calibration confirmed working where wired
(HR +0.034, OUTS +0.015 overconf). Also found: all prediction calibrators were
13 days stale (a retrain does NOT refit them), and HR never logged `book`.

**Weekly-trend reclassification (key nuance).** The rolling-30 gate can't tell a
consistent loser from one bad week. The 05-05..06-22 trend showed:
- True no-edge losers (AUC ~0.50, negative most/every week): **1IOU, F5, F1H**.
- Volatile / one-bad-week (do NOT retrain reactively): **OUTS** (positive 5 of 7
  weeks; -46% rolling is the single 06-22 week, n=10), **HR** (longshot variance,
  AUC 0.627), **K** and **BATTER_HITS** (healthy, one off week).

**Shipped + deployed.**

- PR #16 (merged) -- retire the no-edge set: `1IOU` + `F5` via registry
  `force_gate="on"`; `F1H` via `run_f5` `LOG_ONLY_SYSTEMS`. All still log
  predictions (kelly_triggered=False); reversible after retrain.

  created `mlb-fit-calibrators-weekly` scheduler (Mon 10:00 UTC).

  `force_gate` is baked into the image -> suppression active on the next `/run`
