# Beezy.FYI UI/UX Audit — 2026-06-10

Implementation spec for a Sonnet session. Desktop + mobile deep dive of the
public site (`beezy-vip/`). Every item cites `file:line`, states the problem,
the requirement, and acceptance criteria. Work top-down: P0 first.

**Ground rules (from CONTEXT.md §13 Design system):**
- Colors: bg `#0a0a0c`, surface `#111114`, border `#1f1f24`, hard frame `#000`,
  muted text `#888890`, links `#9999ff`, CTA `#fcc20f`. Tints: sage `#b3bd95`
  (win), salmon `#d77a7a` (loss), sky `#9ab6c8`, peach `#e6915d`, lime `#c0d4a7`,
  steel `#a5b8c0`.
- Typography: `.dell-display` (Arial Black), `.dell-heading` (Arial 700),
  `.times` (Georgia), `.mono` (JetBrains Mono). No other font families.
- `borderRadius: 0` everywhere. `1px solid` borders. No gradients. No shadows/glows.
- Import `B`, `SYSTEM_COLOR`, `SYSTEM_PILL`, `pickLabel` from `@/lib/tokens`.

Do NOT touch `/api/og/*` routes or `legal/*` pages (intentionally excluded).
Run `npm test` before any commit that touches schema/util code.

## P0 — Design-system violations (the cheat-sheet is an island)

The flagship share surface (`app/cheat-sheet/cheat-sheet-client.tsx`) opted out of
the Dell system: it uses Inter, a gradient, and a completely separate gray ramp
(`#07070b`, `#08080d`, `#0d0d12`, `#06060a`, `#0a0a0f`, `#23232d`, `#2a2a36`,
`#1a1a22`, `#626274`, `#797991`, `#3f3f4e`, `#52525b`). None of these are tokens.
This is the single biggest source of the "piecemeal" feel because it is the most
screenshotted, most shared page.

### P0-1 — Cheat-sheet uses Inter instead of the Dell font stack
- File: `app/cheat-sheet/cheat-sheet-client.tsx:282`
- Problem: `fontFamily: 'Inter, -apple-system, sans-serif'` on the page wrapper.
  Every other surface uses Arial / Georgia / JetBrains Mono. The card's body text
  renders in a different typeface than the site it represents.
- Requirement: Remove the `fontFamily` override (let it inherit the global Arial),
  OR set it to `'Arial, Helvetica, sans-serif'`. Keep `.mono` / `.dell-*` class
  usage as-is.
- Acceptance: No `Inter` reference remains in the file. Card body text matches
  the picks table typography.

### P0-2 — Cheat-sheet header uses a gradient
- File: `app/cheat-sheet/cheat-sheet-client.tsx:294`
- Problem: `background: 'linear-gradient(135deg, #0f2017 0%, #09090f 64%)'`
  violates the no-gradients rule.
- Requirement: Replace with a flat fill. Use `#0f1a14` (the hero stat-card dark
  green) or `#0a0a0c`. Pick one; keep the bottom border `1px solid #1f1f24`.
- Acceptance: No `linear-gradient` in the file.

### P0-3 — Consolidate the cheat-sheet gray ramp to tokens
- File: `app/cheat-sheet/cheat-sheet-client.tsx` (throughout)
- Problem: ~10 off-palette grays. Map them to the token set:
  | Current | Lines (examples) | Replace with |
  |---|---|---|
  | `#07070b`, `#08080d`, `#06060a`, `#0a0a0f`, `#0d0d12` | 276, 288, 509, 398/429/472, 89 | `#0a0a0c` (bg) or `#111114` (surface) — see note |
  | `#23232d`, `#2a2a36` | 287, 329/362/382 | `#1f1f24` (border) or `#2a2a31` (border-bright) |
  | `#1a1a22` | 296, 399, 428, 474, 504 | `#1f1f24` |
  | `#626274`, `#797991` | 200/214? , 215 | `#888890` (muted) |
  | `#3f3f4e` | 433, 436, 511, 514 | `#888890` for readable micro-labels; `#52525b` only if truly decorative |
  | `#52525b` | 446, 526 | `#888890` |
  Note: keep a TWO-level surface system (outer card darker than inner rows) but
  use only `#0a0a0c` (outer) and `#111114`/`#0d0d10` (rows). Do not invent new hexes.
- Acceptance: Every hex in the file is either a documented token, a `SYSTEM_COLOR`
  tint, or `#000`. Contrast of all text vs its background ≥ 4.5:1 for body, ≥ 3:1
  for large/label text.

### P0-4 — Stray `borderRadius` var references in cheat-sheet
- File: `app/cheat-sheet/cheat-sheet-client.tsx:289` (`var(--radius-lg)`),
  `:330` (`var(--radius-sm)`)
- Problem: These resolve to `0` today (vars were zeroed) so they're harmless, but
  they're misleading and will silently re-round if the vars ever change.
- Requirement: Replace with literal `borderRadius: 0` (or remove the property).
- Acceptance: No `var(--radius` references remain in the file.

## P1 — Mobile usability

### P1-1 — Interactive touch targets below 40px
WCAG 2.5.5 / Apple HIG want ~44px. These controls are tappable but cramped:
- `components/picks/filter-bar.tsx:14` — `CHIP_BASE` padding `5px 10px` (~25px tall)
- `components/picks/filter-bar.tsx` sort/toggle buttons (`4px 8px`–`5px 10px`)
- `components/picks/date-bar.tsx:39,46` — prev/next/date buttons (`4px 10–13px`, ~20px)
- `components/picks/picks-table.tsx:404-416` — pagination buttons (`6px 12px`, ~27px)
- `components/ui/copy-bet-button.tsx:32` — copy button (`2px 8px`, ~18px)
- `app/cheat-sheet/cheat-sheet-client.tsx:354,374` — expand/all + filter chips
- Requirement: On coarse pointers, give all genuinely-interactive controls a
  `minHeight: 40px` (or `44px` for primary actions) and adequate horizontal
  padding. Easiest implementation: add a touch-only rule in `globals.css`:
  ```css
  @media (hover: none) and (pointer: coarse) {
    button, [role="button"], a.btn { min-height: 40px; }
  }
  ```
  Then add `className="btn"` (or a shared style) to the controls above. Do NOT
  enlarge non-interactive badges (ResultPill, SystemBadge, ScoreBadge tier label).
- Acceptance: On a 390px viewport, every button/clickable chip has a tap target
  ≥ 40px tall. Badges and labels unchanged.

### P1-2 — Bottom-nav label font is 8px
- File: `components/layout/bottom-nav.tsx:59`
- Problem: 8px tab labels ("Card", "Picks", …) are below comfortable legibility.
  The container is 56px so there is room.
- Requirement: Bump label to `9px` (10px if it still fits one line), icon stays 17px.
  Verify the 5 labels don't wrap at 360px width.
- Acceptance: Labels readable at arm's length on a phone; no wrapping at 360px.

### P1-3 — Tablet-range horizontal scroll on the picks/results tables
- Files: `components/picks/picks-table.tsx:11-12` (`TABLE_MIN_WIDTH 1120px`),
  results equivalent.
- Problem: Mobile card view kicks in only at ≤768px. Between 769–1119px (tablets
  landscape, small laptops) the 1120px table forces horizontal scroll inside the
  page. Desktop (≥1160px content) is fine; <768px uses cards; the 768–1119 band
  is the gap.
- Requirement: Either (a) raise the mobile-card breakpoint to ~900px so tablets
  get cards, or (b) reduce `TABLE_MIN_WIDTH` by tightening column mins
  (`TABLE_GRID` at `:11`) so the table fits ~960px. Prefer (a) — cards read better
  on touch.
- Acceptance: No horizontal page scroll at 768px or 1024px on /picks and /results.

### P1-4 — Cheat-sheet low-contrast sub text
- File: `app/cheat-sheet/cheat-sheet-client.tsx:200-201` (`#626274` on `#0d0d12`)
- Problem: Pick sub-line (bet type / odds / book) is ~3:1 contrast — hard to read,
  and this is the line a bettor actually needs.
- Requirement: Lift to `#888890` (covered by P0-3 but call out explicitly — the
  sub line is functional data, not decoration).
- Acceptance: Sub line ≥ 4.5:1 contrast.

## P2 — Information architecture & flow

### P2-1 — Landing section order asks for Discord before explaining the product
- File: `app/page.tsx:18-27`
- Problem: Order is Hero → RecentPicksTable → **DiscordFollowCTA** → HowItWorks →
  ModelsGrid. A first-time visitor is asked to join Discord before "How it works"
  has explained what Beezy is.
- Requirement: Reorder to Hero → RecentPicksTable → **HowItWorks** → ModelsGrid →
  **DiscordFollowCTA**. Put the social CTA after the value prop and proof.
- Acceptance: HowItWorks renders above the Discord CTA. Suspense boundaries kept.

### P2-2 — Cheat-sheet has no share/download action (the social flywheel)
- File: `app/cheat-sheet/cheat-sheet-client.tsx:503-533` (footer area)
- Problem: The card exists to be screenshotted into Discord, but there is no
  Share or Download button. Only a "FULL PICKS TABLE" text link. (Backlog F-7.4.)
- Requirement: Add a primary action button (CTA yellow `#fcc20f`, black text,
  `borderRadius: 0`) labeled "SHARE CARD". Use the Web Share API
  (`navigator.share`) when available; fallback to copying `https://beezy.fyi/cheat-sheet`
  to clipboard with a toast. Stretch: call `/api/og/picks-card` to download the
  generated image. Place it in the footer row, left of the wordmark.
- Acceptance: Tapping Share opens the native share sheet on mobile; on desktop it
  copies the link and confirms. Button matches Dell button styling.

### P2-3 — Cheat-sheet empty state is a dead end
- File: `app/cheat-sheet/cheat-sheet-client.tsx:441-449`
- Problem: When there are no picks, the card shows "The next card appears after the
  model run." No value, no reason to stay. (Backlog F-7.3.)
- Requirement: When `filtered.length === 0`, show yesterday's top 3 settled results
  (W/L badges) + a one-line record line + "Next card ~11am ET." Requires passing
  yesterday's settled picks from the server component (`app/cheat-sheet/page.tsx`).
- Acceptance: Empty state shows prior-day proof, not just a waiting message.

### P2-4 — Trailing divider on the last desktop nav link
- File: `components/layout/nav.tsx:54` (`borderRight: '1px solid #1a1a1a'` on every link)
- Problem: The last link ("Learn") renders a trailing right border before the gap
  to the auth cluster — a hanging divider.
- Requirement: Drop `borderRight` on the last item (`index === NAV_LINKS.length-1`),
  or use `borderLeft` on all-but-first. Also `#1a1a1a` is off-palette → use `#1f1f24`.
- Acceptance: No hanging divider after "Learn"; divider color is `#1f1f24`.

## P3 — Polish & consistency

### P3-1 — `0.5px` borders still present in globals.css mobile rules
- File: `app/globals.css:251,282,287` (`border-top/bottom: 0.5px solid #1f1f24`)
- Problem: The Dell rule is `1px solid`. These mobile-only `0.5px` borders are
  leftovers; `0.5px` renders inconsistently across DPRs (invisible on some).
- Requirement: Change all `0.5px` → `1px` in globals.css.
- Acceptance: `grep "0.5px" app/globals.css` returns nothing.

### P3-2 — Off-palette grays in slate / live-ticker / table micro-text
- Files: `components/today/slate-strip.tsx`, `components/picks/picks-table.tsx`
  (`#3f3f46`, `#27272a`, `#52525b`, `#626274` in notes/labels), `live-ticker.tsx`
- Problem: A scattering of zinc grays (`#3f3f46`, `#27272a`, `#52525b`) that predate
  the Dell sweep persist in low-emphasis text.
- Requirement: Map decorative/disabled text to `#52525b`→`#888890` where it's
  meant to be read; keep one "faint" gray (`#3f3f46`) only for truly decorative
  separators. Document the chosen faint gray as a token if kept.
- Acceptance: Functional text (notes, odds, labels) is `#888890` or a tint; no
  zinc `#27272a`/`#3f3f46` on text the user must read.

### P3-3 — Cheat-sheet card max-width vs desktop viewing
- File: `app/cheat-sheet/cheat-sheet-client.tsx:286` (`maxWidth: '390px'`)
- Problem: The card is locked to 390px even on desktop, leaving a vast empty dark
  field on /cheat-sheet when viewed on a laptop. Fine for the screenshot artifact,
  awkward as a page.
- Requirement: Keep 390px for the card, but on desktop add context beside/around
  it (e.g., a short "what is this" panel or the slate strip) OR center it with a
  subtle framed backdrop so it reads intentionally, not broken.
- Acceptance: /cheat-sheet on a 1440px screen does not look like a rendering error.

### P3-4 — Hero secondary CTA border uses rgba white
- File: `components/landing/hero.tsx:97` (`border: '1px solid rgba(255,255,255,0.5)'`)
- Problem: Soft translucent border is a holdover aesthetic; on the new dark-green
  panel it reads muddy. Dell wants hard edges.
- Requirement: Use a solid `1px solid #fff` (or `#fcc20f` to tie to brand) for the
  "View Methodology" button border.
- Acceptance: Secondary CTA has a crisp 1px border matching the Dell look.
